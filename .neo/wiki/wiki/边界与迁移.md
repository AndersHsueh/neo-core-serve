# 边界与迁移

> 最后更新:2026-10-28

## 摘要

三仓（`neo` CLI / `neo-core-serve` / `neo-agent-app`）完全独立，无代码依赖（无 file:、workspace、submodule、包注册表），唯一契约是 WS 协议 + fixtures + 文档。迁移策略：neo v0.4.3 冻结 → 分两批移植（C0b 纯模块、C1 agent/tools 先建端口）→ 本仓为唯一真源 → GUI 先接 → CLI 后续改纯客户端（C5）。过渡期与 neo CLI 共享 `~/.neo`，因此有明确的共存规则：锁互认、路径从 id 重算、日志分区、只读 import/备份、禁止同一会话双开。

## 迁移步骤

1. **冻结** neo v0.4.3（`1da7c6f`），只 critical hotfix。
2. **C0b**：只搬纯模块（llm/config/classifier/memory/wiki/mailbox/env/skills/session/checkpoint/shell/…）与对应测试；agent/tools 不搬（它们 import `ui/*`，会编译不过）。
3. **C1**：建 ports（EventSink/Approval/Question/PathPolicy/Clock/…）后搬 agent/tools，事件化、组合根、命令层。
4. **C2**：serve/WS/stdio、持久化/锁/恢复、GUI conformance。
5. **C5（另立）**：neo CLI 改纯客户端；删除内嵌 runtime。

## 共存规则（D15）

- **锁互认**：core `run/locks/<id>` 与 neo mailbox `.alive` 任一存在 → 拒绝双开；pid/心跳过期回收。
- **路径**：从 session id 重算 `~/.neo/sessions/<id>.json`，不信任 JSON 里的 `meta.path`。
- **日志分区**：core 只写 `logs/core/`；`logs/turns/` 容忍并发；maintenance 只碰自己命名空间。
- **交替使用**：允许先 CLI 后 core（core 打开时对账重建）；**禁止同时**。
- **导入/迁移**：`matrix-core import <id>` 只读验证 + `backup`；旧会话无 transcript → 有损重建并标 degraded。

## 为什么拒绝 file:/submodule

发布/CI/版本会互相锁死；客户端本来就必须走协议；代码共享没有必要。代价是过渡期两份代码，用「冻结 + 快速切换」压缩窗口。
