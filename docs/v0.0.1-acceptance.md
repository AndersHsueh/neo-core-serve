## 5. 已知限制（v0.0.1）

**范围**
1. **单会话**：一进程 = 一会话；无 Hub、无会话注册表、无 worker 池。
2. **无附件/图片**：`turn.send` 只接受 text。
3. **未实现的协议命令**：`command.cancel`、`transcript.fetch`、`output.get`、`checkpoint.*`、`session.export`、`peers.list`（→ guards 报 `protocol`）；`session.close`、`settings.patch`、`auth.*`（→ `unsupported`）。
4. **`matrix-core import`、`--force` 接管、`doctor` 完整自检**：未交付（v0.0.2）。
5. **usage 空计量**：`costMicros=0`，客户端显示「未计价」。

**架构偏差（v0.0.2 收口，见 [release notes](release-notes/v0.0.1.md)）**
6. **`core/ui` 兼容层保留**：移植的 `agent/tools` 仍依赖 `src/core/ui/*`，「core 零 ui」未完全达成。
7. **快照由 host 生成**：`core/session-host.ts` 运行时 `import { applyEvent } from "../protocol/reducer.ts"`；架构 §5.4 要求由 serve 用 reducer 生成快照。v0.0.2 移到 serve。
8. **崩溃恢复比架构保守**：一律补 `turn.aborted{reason:"crash"}`，不按 `meta.lastTurn` 补 `stats`（架构 §7.2 的"视为完成"分支未实现）。
9. **无 WS 合批/背压**：协议 §9 的 16ms/4KB 合批、512 帧/8MB 上限、4408 断开未实现（v0.0.2）。
10. **`/health` 的 `state` 恒为 `idle`**、`protocolVersion` 为字面量（v0.0.2 接真实状态/常量）。

**审批与提问**
11. **allow-session 为内存白名单**：仅按工具名 `write_file/edit_file` 记忆；`shell` 永不记忆。**没有 cwd/路径校验**（PathPolicy 未交付，见 I4）；不落盘，进程退出即失效。
12. **断线宽限 / `no_client` / deadline 滑动续期**：未交付（v0.0.2）。审批/提问只按固定超时收敛：审批默认 120s、提问默认 300s（`MATRIX_CORE_APPROVAL_TIMEOUT_MS` / `MATRIX_CORE_QUESTION_TIMEOUT_MS` 可注入）。
13. **审批不带 `path`/`diff`**：`approval.request` 只带 `tool/detail`；capabilities 不广告 `approval.diff.optional`。

**能力位与平台**
14. **capabilities 只广告实际能力**（6 项）：`turn.aborted`、`command.structured`、`mode.set`、`snapshot.live`、`activity`、`question.multi`。不含 `transcript.replay`/`peers`/`approval.diff.optional` → 客户端不得期待服务端补发增量（attach 一律快照）。
15. **无打包**：未做 `bun build --compile` 单文件分发；仅 `bun run` / `bun link`。
16. **平台**：仅 macOS 实机验证；Windows 不支持，Linux 未实机验收。
17. **恢复粒度**：以轮为单位，不承诺 fsync 级持久性。

## 6. 上手（Quick start）

### 6.1 前置

- Bun ≥ 1.3（`bun --version`）
- 本地 LLM 配置 `settings.json`（**含 API key，已被 `.gitignore` 忽略**，勿提交）；配置查找顺序：`--cwd` 的 `settings.json` → 包根 → `~/.neo/settings.json`（取第一个存在的，不合并）。

```json
{
  "default_provider": "ipsa",
  "providers": [
    {
      "provider_name": "ipsa",
      "provider_type": "openai",
      "base_url": "https://your-gateway/v1",
      "api_key": "sk-…",
      "default_model_name": "deepseek-flash"
    }
  ]
}
```

### 6.2 零依赖验证（fake LLM，推荐）

```bash
# 终端 1：起假 LLM。PORT=0 自动选端口，stdout 打印 FAKE_LLM_READY port=<n>
PORT=0 SCENARIO=tool-then-answer bun run scripts/fake-llm.ts

# 终端 2：起 core（stdio），指向假 LLM
NEO_BASE_URL=http://127.0.0.1:<port>/v1 NEO_API_KEY=fake NEO_MODEL=fake-model \
  bun run src/main.ts serve --stdio --cwd /tmp/work
```

> 场景：`tool-then-answer | narration | ask-user | write-then-answer | slow | resume`。
> 需要 `--cwd` 下有一份指向假 LLM 的 `settings.json`（见 `tests/helpers.ts` 的 `fakeSettings`）。

### 6.3 stdio 一轮

```jsonc
{"v":1,"kind":"command","id":"1","command":{"type":"session.list"}}
{"v":1,"kind":"command","id":"2","command":{"type":"turn.send","text":"hi","clientId":"c1"}}
```

### 6.4 WS 一轮

```bash
matrix-core serve --cwd /path/to/project      # 写 ~/.neo/run/core.json
cat ~/.neo/run/core.json                     # {url,pid,tokenFile,sessionId,epoch}
TOKEN=$(cat ~/.neo/run/core.token)
curl -s http://127.0.0.1:<port>/health
# 客户端以子协议 ["neo.v1","bearer.$TOKEN"] 连 ws://127.0.0.1:<port>/ws
```

### 6.5 生命周期

```bash
matrix-core status    # 读 core.json + pid 存活（alive 字段）
matrix-core stop      # 向 pid 发 SIGTERM（优雅关闭：abort → flush → persist → 释放锁）
matrix-core doctor    # run 目录 / token / core.json 自检（最小实现）
```

## 7. 排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `ready` 收不到 | token 错 / 端口不对 / 子协议缺失 | 读 `core.json`；确认 `bearer.<token>`；看 stderr |
| WS 401 | token 轮换（重启会换） | 客户端重读 `core.json` + `core.token` |
| `conflict` on `turn.send` | 上一轮还在 working | 等 `stats`/`turn.aborted`；或 `turn.abort` |
| 启动即退出 `conflict` | 同会话已有实例持锁 | `matrix-core status`；确认旧进程退出后重试 |
| 审批卡住 | 无客户端在线 / 超时策略 | 目前只按固定超时收敛（见 §5.12）；重启恢复 |
| 恢复后少一轮 | 半轮被判定为 crash | 预期（保守策略，见 §5.8）；查 `logs/turns/` |
| `docs:check` 报 lock 不一致 | 改了 `src/protocol/**` 未重冻 | `bun run freeze:protocol`（仅 Lead） |
| stdout 出现非帧文本 | 走了终端渲染路径（回归） | 报告 Lead；core 不得写 ANSI |
