## 2. 功能与接口

### 2.1 PathPolicy（coder）
`src/core/path.ts`：
```ts
export interface PathPolicy { resolveRead(p: string): string; resolveWrite(p: string): string; }
export function createPathPolicy(cwd: string): PathPolicy;
```
- resolveRead：存在性检查 + realpath（解析 symlink）+ 必须位于 cwd 内（含 cwd 本身）；`..` 逃逸、绝对外部路径、symlink 逃逸 → throw `PathDeniedError`。
- resolveWrite：目标可不存在；对父目录 realpath 后校验；写入后仍可能 symlink 变换（记录为已知，v0.0.3 加 O_NOFOLLOW）。
- 接入：tools 的 read/write/edit/list_dir/glob/grep（路径参数）、checkpoint undo、`@refs` 解析、session export 路径；**shell 与显式用户级目录（~/.neo/skills、~/.neo/memory、项目 wiki）不受限**。
- 测试：`../../etc/passwd`、`/etc/passwd`、symlink 指向外部、cwd 内绝对/相对都允许。

### 2.2 三处统一（coder + Lead）
1) `src/core/paths.ts`：`neoHome(dir)` / `sessionsDir()` / `transcriptsDir()` / `runDir()` / `locksDir()` / `sessionPath(id)` / `tokenFile()` / `runFile()`；host、auth、main、session.ts 全部改用它（允许 `NEO_*` 覆盖）。
2) `src/core/commands/registry.ts`：单表 `{name, aliases, group, args, description, run(ctx,args)}`；`runCommand` switch、`COMMAND_SUBSET`、HELP_TEXT、未知命令错误全部由表派生；生成 `src/protocol/commands.json`（Lead 的 `docs:check` 校验）。
3) `src/serve/frames.ts`：`decodeFrame()` 从 stdio 抽出，stdio/ws 共用；去掉重复分支。
4) reducer per-delta 优化（coder）：对 `assistant.delta`/`reasoning.delta` 走快路径（只改当前 block，不 clone 全 blocks/segments）；durable 事件仍用 protocol reducer；快照一致性测试必须绿。

### 2.3 WS 合批/背压 + transcript.fetch（Lead）
- `src/serve/batcher.ts`：每连接队列；16ms 或 4KB flush；同 block delta 合并（保留最新 seq）；队列 >512 帧/8MB 时先丢 ephemeral，仍超限关闭 4408。
- `transcript.fetch {sessionId?, fromSeq?, limit?}` → `{events:[{seq,event}], nextSeq?}`；能力位加 `transcript.replay`。
- attach{lastSeq,epoch}：epoch 匹配且 lastSeq 可补齐时回放 durable 事件（经 batcher），否则快照；v0.0.2 至少实现 fetch。
- 帧上限：普通 1MB；带附件 8MB（见 2.5）。

### 2.4 多会话 Hub + worker（Lead + coder 配合）
- `matrix-core hub [--port 0] [--dev-auth] [--token-file] [--cwd <默认目录>]`。
- Hub 自己进程内**不跑 Agent**；每会话 spawn 一个 `matrix-core serve --stdio --cwd <dir> [--resume id]` worker。
- Hub WS 协议：
  - `ready` 增加 `capabilities: [...,"sessions"]`。
  - `session.list` → `{sessions: SessionMeta[]}`（磁盘 + 运行中）。
  - `session.create {title?,cwd?}` → spawn worker → `{sessionId}`。
  - `session.attach {sessionId,lastSeq?,epoch?}` → spawn/reuse worker，返回 `{role}` + snapshot；连接与 session 绑定。
  - `session.detach/close`；close 终止 worker。
  - `turn.send/abort/approval.resolve/question.answer/command.run/settings.get/usage.summary` 转发给当前绑定的 worker，结果/事件回传（事件带 sessionId/seq）。
  - 未 attach 的会话命令 → `conflict`。
- worker 生命周期：空闲 30min 回收（可配）、崩溃重启指数退避、Hub 退出时全部 SIGTERM；日志走 stderr。
- v0.0.2 简化为「一个 session 同时一个客户端」；第二个 attach → `conflict`。
- 测试：起 Hub（stdio? 不行——Hub 是 WS；测试用 WS 客户端），两 session 并行 turn、session.list、close、worker 崩溃恢复（至少 kill worker 后可 attach 恢复）。

### 2.5 附件/图片（coder + Lead）
- 协议 `turn.send` 增加可选 `attachments: {kind:"image"; mime:string; dataBase64:string}[]`（≤5 张，单张 ≤5MB，仅 png/jpeg/webp）。
- Host 解码：写 `sessions/attachments/<sessionId>/img-N.<ext>`，用户消息 content 增加 `image_url` part；会话 JSON 用 `$ref`（沿用 session.ts hydrate）。
- 帧上限：WS/stdio 允许带附件到 8MB；超限返回 `protocol`/`too_large`（HubErrorCode 可加 `too_large`）。
- 测试：微型 PNG base64 发送→fake LLM 收到 image_url（`/_requests` 断言）→落盘 $ref→resume 后 hydrate 回来。

### 2.6 配置（Lead + coder）
- GUI 联调统一使用 `~/.neo/settings.json`：
  - `loadConfig` 搜索顺序保持 cwd/settings.json → 包根 → `~/.neo/settings.json`；
  - Hub/worker 的 `--cwd` 默认用户项目目录；若项目无 settings.json，自然回落 `~/.neo/settings.json`；
  - 文档明确：GUI 联调前把 settings 放 `~/.neo/settings.json`，不要放 core 仓库。
- `docs:check` 增加：`commands.json` 与 registry 一致（Lead 生成/校验）。
