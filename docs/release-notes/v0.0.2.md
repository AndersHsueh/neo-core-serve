## 一句话

**v0.0.2 把 Matrix-Core 从「单会话进程」升级为「本地多会话 Hub」**：PathPolicy 收口文件边界、命令目录单表、WS 合批背压 + transcript 回放、图片附件，并交付 GUI 联调指南。

---

## 亮点

- **PathPolicy**：所有工具/refs/export 的文件路径统一 `realpath + cwd 前缀` 校验；`..` 逃逸、外部绝对路径、symlink 逃逸全部拒绝（v0.0.1 的已知安全缺口收口）。
- **多会话 Hub**：`matrix-core hub` 自身不跑 Agent，每会话 spawn 一个 worker（`serve --stdio`），`session.list/create/attach/close` 全覆盖；worker 崩溃可恢复、空闲回收。
- **WS 合批 + 背压**：delta 合批（16ms/4KB）、每连接队列上限（512 帧/8MB）、慢消费者断开 4408；`transcript.fetch` 支持分页回放，`attach{lastSeq,epoch}` 可增量补齐。
- **图片附件**：`turn.send.attachments`（png/jpeg/webp，≤5 张、单张 ≤5MB、帧 ≤8MB），落盘 `$ref`、resume 后 hydrate；超限 `too_large`。
- **GUI 联调就绪**：[gui-integration-v0.0.2.md](../gui-integration-v0.0.2.md) 给出 `~/.neo/settings.json`、`hub --dev-auth`、发现/握手、多会话、事件/seq、附件与验收 checklist；**不改 `neo-agent-app` 代码**。
- **命令目录单表**：`src/protocol/commands.json` 由 core 注册表生成，`docs:check` 校验漂移；help/未知命令错误/客户端命令面板同源。

| 增量 | 说明 |

| `commands.json` | 命令目录单源：`bun run commands:gen` 生成 `src/protocol/commands.json`（当前 24 条：name/aliases/group/args/description/since/core）；客户端 vendor；`docs:check` 校验 registry↔json 漂移 |

## 破坏性变更

**无。** 具体：

- 会话文件 `version:1` 不变；transcript 格式不变（仍 header + durable 行，`seq/event`）。
- 协议判别名未改；只加可选字段/新命令/新事件/新错误码/新 capability。
- 新增目录 `~/.neo/sessions/attachments/<id>/`（旧会话无此目录 = 正常）。
- 新增 `src/protocol/commands.json`（客户端可选 vendor）。
- 版本号 `0.0.1 → 0.0.2`（`package.json` 与 `src/main.ts CORE_VERSION` 同步，`docs:check` 校验）。

## 升级 / 回滚

### 升级（v0.0.1 → v0.0.2）

- 同一 `~/.neo` 直接可用；建议先备份 `~/.neo/sessions`。
- 客户端（GUI）：按 [gui-integration-v0.0.2.md](../gui-integration-v0.0.2.md) 更新 vendored 协议 + `commands.json` + `protocol.lock.json`，再开多会话/附件 UI；旧客户端可不改、继续单会话连 `serve`。
- 配置：GUI 联调推荐 `~/.neo/settings.json`（不要放 core 仓库）；项目级 settings 仍优先。
- 单会话 `serve` 行为与 v0.0.1 兼容（协议只加不改）。

### 回滚（v0.0.2 → v0.0.1）

- 保留 `v0.0.1` tag；回滚二进制/源码即可。
- 会话/transcript 格式未变 → v0.0.1 可直接读；附件目录被忽略（无附件能力）。
- v0.0.1 客户端 vendor 的协议不含新字段/命令，遇到 v0.0.2 写入的 `attachments` 消息会按未知字段忽略（不影响历史文本）；不要用 v0.0.1 继续发图片。
- `commands.json` 在 v0.0.1 不存在 → 客户端回退手写命令表（或保留 vendor 不影响）。

## 已知问题 / 限制

1. **同一 session 只允许一个客户端**（v0.0.2 简化）；第二个 attach → `conflict`。
2. **Hub 只做本地回环**；无远程/TLS/多租户。
3. **附件仅图片**（png/jpeg/webp），无剪贴板自动粘贴/拖拽通道/缩略图；单张 ≤5MB、每轮 ≤5 张。**历史附件不可回放**：协议 v1.2 不回传附件元数据（刷新/重连后历史图片不显示；模型上下文与磁盘 `$ref` 仍在），v0.0.3 补。
4. **worker 生命周期简化**：**无空闲回收、无自动重启/退避**；worker 崩溃后 Hub 发 `session.status{dead}` 并解绑，需再次 `session.attach` 重新拉起（`--resume`）。Hub 退出时 worker 收 SIGTERM；Hub 异常退出时 worker 因 stdin 关闭自行收尾。
5. `settings.patch`、`session.export`、`checkpoint.*`、`command.cancel`、`peers.list`：仍未交付（见下）。
6. Windows 未实机验收；Linux 未实机验收。
7. 无打包分发（`bun build --compile`）与分发签名。
9. **快照仍在 host 生成**（core 运行时 import `protocol/reducer`），架构 §5.4「快照移 serve」未做（v0.0.1 遗留）。
10. **`core/ui` 兼容层仍在**（agent 的 stream/render/theme + askUser 类型）——v0.0.3 抽 `core/ports.ts` 后删。
11. **`session.attach` 不做增量补齐**：v0.0.2 总快照；`transcript.replay` 能力位已广告，但「补齐」只由 `transcript.fetch` 承担（真正接 attach 留待 v0.0.3）。
