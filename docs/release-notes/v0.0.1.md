# Matrix-Core v0.0.1

> 发布日期：2026-10-28 · 标签：`v0.0.1` · 协议：v1.1（wire v1）
> 上一版本：无（首个版本）· 下游：[验收清单](../v0.0.1-acceptance.md) · [运维手册](../ops.md)

---

## 一句话

**Matrix-Core 第一次能脱离终端独立跑完整一轮**：一个进程、一个会话，WS 或 stdio 驱动，事件落 transcript，崩溃能对账。

---

## 亮点

- **无 TTY 可运行**：`matrix-core serve --stdio` 在纯管道环境跑完整轮（流式 / 思维链 / 工具 / 审批 / 提问 / stats）。
- **协议 v1.1 冻结**：`src/protocol/` 六文件 + `protocol.lock.json` 哈希锁，客户端可 vendor + conformance。
- **会话可恢复**：`messages`（LLM 真源）+ `transcripts/<id>.ndjson`（durable 事件 + seq）+ `epoch`；`--resume` 对账，半轮补 `turn.aborted{crash}`。
- **单写者锁**：`~/.neo/run/locks/<id>/owner.json`（mkdir 独占 + pid 校验 + 陈旧锁回收），并与 mailbox `.alive` 互认；双开返回 `conflict`。
- **两级传输**：本地 WS（`/ws` + `/health` + token 0600）与 stdio 行分隔帧，共用同一套 dispatch。
- **可复现验收**：fake LLM + e2e（25 个：stdio/WS/锁/allow-session/提问/旧会话/中断恢复），不依赖外网与真实 key。

## 协议 v1.1

- **冻结面**：`types/guards/fixtures/reducer/commands/index` 六文件，锁在 `protocol.lock.json`（source commit `a52f1f0`）。
- **v1.1 相对 GUI v1 的加法**（判别名一律未改）：
  - `ready` 增 `coreVersion/protocolVersion/capabilities/sessionId/epoch`
  - `sessionId` 在所有会话命令中**可选**（单会话忽略，兼容 GUI 旧调用）
  - `turn.abort` 增 `turnId`；`question.answer` 增 `keys/custom`、`key` 变可选
  - 新事件：`turn.aborted`、`compact.start/end`、`command.result`、`session.cleared`、`activity`、`notice`
  - 新命令：`mode.set`
  - 语义收紧：`error`/`question.resolve` 必带时间字段；`assistant.end.text` / `reasoning.end.text` 为权威全文；`stats` 增 `blockId/turnId`；`seq` 只在信封上（事件体内不带第二份）
  - 错误码补 `question_expired` / `slow_consumer` / `unsupported`（协议 §8）
- **v0.0.1 的取舍**：
  - `session.attach` **总是返回完整快照**，不按 `lastSeq` 补齐增量；因此 `transcript.replay` 不广告（避免客户端误判）。
  - `session.list` / `usage.summary` 只回 `result.data`（不再同时推 `sessions`/`usage` kind 帧）。
  - 未实现命令（协议 §4.1 标 ❌）：`command.cancel`、`transcript.fetch`、`output.get`、`checkpoint.*`、`session.export`、`peers.list` → guards 报 `protocol`；`session.close`、`settings.patch`、`auth.*` → `unsupported`。
- 细节与客户端改动清单：[protocol-v1.md](../protocol-v1.md) §4/§7。

## 架构偏差与 v0.0.2 清理计划

v0.0.1 的目标是「先能独立跑」，因此刻意保留了一些过渡形态。已在 [provenance.md](../provenance.md) 登记来源，下面是**待清理清单**（v0.0.2 必须收口）：

| # | 偏差 | 现状 | v0.0.2 计划 |
|---|---|---|---|
| 1 | **`core/ui` 兼容层** | `agent` 仍 import `ui/{stream,render,theme}`，`protocol-io`/`tools` 用 `ui/askUser` 的类型；「core 不 import ui」未完全成立。（`console/toolLine/toolLog/transcript/select` 中无用的已在收尾删除，仅存 `askUser/render/stream/theme/select`） | 建 `core/ports.ts`（ApprovalPort/QuestionPort/Logger/Clock），删 `core/ui`，守卫升级为「core 全域禁 ui」 |
| 2 | **快照在 host 生成** | `core/session-host.ts` 运行时 `import { applyEvent } from "../protocol/reducer.ts"`；架构 §5.4 要求 serve 用 reducer 生成快照 | 把 `snapshot()` 移到 `serve/`（host 只暴露 durable 事件与 live 相位），core 恢复零 protocol 运行时依赖 |
| 3 | **命令层未完全领域化** | 命令直接写在 session-host 里，直接产出协议 `ViewBlock`；架构 §11 的 core 领域块 `CommandBlock` + serve 映射未拆 | 抽 `core/commands/`，单一注册表 → 生成 `commands.json`，加漂移守卫 |
| 4 | **PathPolicy 未全量接入** | 文件工具沿用 neo 的路径检查（`insideCwd` 曾定义未用） | 全量包裹 fs/refs/save/export + 负样本测试（架构 §17） |
| 5 | **脱敏边界在最外层** | 依赖移植代码既有处理，未做「EventSink/persist 写前」统一脱敏 | 统一 `redact()` 于 EventSink/persist/logger 边界 + 扫描测试 |
| 6 | **崩溃恢复比架构保守** | 一律补 `turn.aborted{crash}`；不按 `meta.lastTurn` 补 `stats`（架构 §7.2「视为完成」分支未实现） | 补「已完成轮」对账分支 + 混沌测试（kill -9 各时机） |
| 7 | **审批语义简化** | allow-session 是内存白名单（仅按工具名 write/edit，shell 不记忆；**无 cwd 校验**）；**无** owner 断线宽限、`no_client`、deadline 滑动续期；审批不带 `path/diff` | 接 liveness 续期 + `no_client` 收敛 + diff 透传（架构 §8.2） |
| 8 | **WS 无流控** | 无 16ms/4KB 合批、无 512 帧/8MB 队列上限、无 4408 断开；`/health` 的 `state` 恒为 `idle` | 合批/背压/慢消费者断开；`/health` 接真实状态与 `PROTOCOL_SEMVER` |
| 9 | **`status/stop/doctor` 最小实现** | 能跑，但 doctor 只查 run 目录/token/core.json；无 `--force` 接管；`matrix-core import` 未实现 | 补 pid 校验与接管、doctor 自检项（配置/端口/LLM/版本）、只读 import |
| 10 | **日志未分区** | 沿用移植 logger，`logs/core/` 命名空间未强制 | logger 注入 + 分区 + 脱敏断言 |
| 11 | **测试覆盖** | stdio 13 + WS 3 + 锁 1 + allow-session 1；混沌（kill -9、慢读、磁盘只读）未自动化 | 补混沌与 golden 事件序列 |

> 这些偏差**不影响 v0.0.1 的单会话使用**，但会阻塞 v0.0.2 的多会话/安全验收；不清理就进下一阶段等于把债务滚大。

## 升级 / 回滚

### 升级

- v0.0.1 是首个版本，无「从旧 core 升级」路径。
- 与 **neo CLI 共存**：共用 `~/.neo`（sessions/mailbox/logs）；同一 session id 禁止双开（core 锁 + CLI `.alive` 互认）。切换前建议备份 `~/.neo/sessions`。
- 协议：客户端按 [protocol-v1.md](../protocol-v1.md) §7 适配（`ready` 字段、可选 sessionId、新事件、`assistant.end.text` 权威、seq/epoch 追踪、只广告的 capabilities 子集）。
- `~/.neo/run/core.json` 为原子写；升级后客户端应重读该文件与 `core.token`（重启会轮换 token）。

### 回滚

- 保留 tag `v0.0.1`；回滚到上一可运行快照（仅 version/help 的骨架）不影响会话数据。
- 会话文件 `version:1` 向后兼容；transcript 只追加，回滚不破坏数据。
- 回滚后旧 core 不认新 transcript → 从 `messages` 有损重建（标 degraded，新 epoch），不丢已提交消息。
- 残留 `run/locks/<id>/`：持锁进程已死则下次启动自动回收；也可手工确认无进程后删除该目录。

## 已知问题

1. 单会话；GUI 多会话不可用。
2. 附件、`transcript.fetch`、`checkpoint.*`、`session.export`、`peers.list` 等未交付（协议 v1.2）。
3. `usage` 为空计量（`costMicros=0`）。
4. 审批无断线宽限/`no_client`/滑动 deadline；只按固定超时收敛。
5. WS 无合批/背压；慢消费者会拖慢进程（v0.0.2）。
6. 崩溃恢复以轮为单位（保守标 aborted），不承诺 fsync。
7. 仅 macOS 实机验证；Windows 不支持。
8. 改 `src/protocol/**` 后必须 `bun run freeze:protocol` 重写 lock，否则 `docs:check` 必红。
