## 5. 已知限制（v0.0.2）

1. **同一 session 同时只允许一个客户端 attach**（v0.0.2 简化；第二个 → `conflict`）。
2. **Hub 仅本地回环**，无远程/TLS/多租户。
3. **附件仅图片**（png/jpeg/webp），无剪贴板自动粘贴、拖拽通道、缩略图；≤5 张/轮、单张 ≤5MB、帧 ≤8MB。
4. **worker 生命周期最小实现**：**无空闲回收、无自动重启/退避**；worker 崩溃后 Hub 发 `session.status{dead}` 并解绑，需再次 attach 重新拉起（`--resume`）。Hub 退出时 worker 收 SIGTERM；Hub 异常退出时 worker 因 stdin 关闭自行收尾。
5. **`resolveWrite` 写入后 symlink 变化**：已知风险（v0.0.3 用 O_NOFOLLOW 收口）。
7. **`settings.patch`/`session.export`/`checkpoint.*`/`command.cancel`/`peers.list`** 仍未交付。
8. **平台**：macOS 实机验证；Windows/Linux 未实机验收。
9. **无打包分发**（`bun build --compile`/签名）。
10. **Hub 级观测**：沿用 v0.0.1 的 status/stop/doctor；无 Hub 指标/结构化日志分区（`/health` 只给 `mode:"hub"`+`sessions` 数）。
11. **快照仍在 host 生成**：`core/session-host.ts` 运行时 import `../protocol/reducer.ts`（快照移 serve 未做，属 v0.0.1 遗留；架构 §5.4 目标未达成）。
12. **`core/ui` 兼容层仍在**：agent 的 stream/render/theme + askUser 类型；删 ui 需先抽 `core/ports.ts`（v0.0.3）。
13. **`transcript.fetch` 无独立审计**：`session.attach` v0.0.2 总快照；增量回放/`transcript.replay` 的「补齐」语义只由 fetch 承担（v0.0.3 真正接 attach）。

## 6. 上手（Quick start）

### 6.1 前置

- Bun ≥ 1.3；LLM 配置放 **`~/.neo/settings.json`**（推荐，GUI 联调同款；查找顺序 cwd → 包根 → `~/.neo`）：

```jsonc
{
  "default_provider": "ipsa",
  "providers": [{
    "provider_name": "ipsa", "provider_type": "openai",
    "base_url": "https://your-gateway/v1", "api_key": "sk-…",
    "default_model_name": "deepseek-flash"
  }]
}
```

### 6.2 单会话（v0.0.1 用法不变）

```bash
bun run src/main.ts serve --stdio            # 测试/嵌入
bun run src/main.ts serve --cwd ~/proj       # WS + core.json
```

### 6.3 Hub 多会话（GUI 联调）

```bash
bun run src/main.ts hub --port 0 --dev-auth --cwd ~/projects
cat ~/.neo/run/core.json                     # url/pid/tokenFile
curl -s http://127.0.0.1:<port>/health
# GUI: POST /api/auth/login → token → WS ["neo.v1","bearer.<token>"]
#      session.list → session.create → session.attach → turn.send（详见联调指南）
```

### 6.4 fake LLM（无外网验证）

```bash
# 终端1：支持 tool/ask-user/write/allow-session/附件场景（新增场景以 scripts/fake-llm.ts 为准）
PORT=0 SCENARIO=tool-then-answer bun run scripts/fake-llm.ts

# 终端2：把 cwd 的 settings.json 指向 fake LLM（或直接 ~/.neo/settings.json）
NEO_BASE_URL=http://127.0.0.1:<port>/v1 NEO_API_KEY=fake NEO_MODEL=fake-model \
  bun run src/main.ts hub --dev-auth --cwd /tmp/work
```

> Hub 本身不跑 Agent：LLM 连不通只影响 worker 的 turn（`stats.error`），不影响 Hub 启动/session.list。

| `conflict` attach | 会话已被另一客户端占用（v0.0.2 单客户端） | 关闭另一端；或 `session.detach` 后重试 |
| 未 attach 报 `conflict` | 先发会话命令 | 先 `session.attach` |
| worker 起不来 | cwd 不存在 / settings 无 provider / resume id 不存在 | 看 Hub stderr；单独 `serve --cwd …` 复现；`doctor` |
| 慢客户端被断 4408 | 队列 512 帧/8MB 超限 | 客户端退避重连；以 snapshot 重建 |
| 附件 `too_large` | 张数/大小/帧上限 | 压缩、减张数；确认 mime |
| 图片历史不到 | `$ref` 未 hydrate / 附件目录被删 | 不要删 `sessions/attachments`；重启/attach 重建 |
| `/help` 与 `commands.json` 不一致 | 未生成命令目录 | `bun run <生成脚本>`（以 Lead 命令为准）；`docs:check` 会红 |
| 工具报路径拒绝 | 目标在 cwd 外（PathPolicy） | 换 cwd 内路径；用户级目录（skills/memory/wiki）是豁免项 |
